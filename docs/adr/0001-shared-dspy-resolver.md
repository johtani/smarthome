# ADR 0001　本番とオフライン評価で単一段の DSPy コマンド resolver を共有する

## 状態

採用済み。[Issue #210](https://github.com/johtani/smarthome/issues/210) で検討し、[PR #216](https://github.com/johtani/smarthome/pull/216) で導入した。

## 背景

本番のコマンド解決は1回の LM 呼び出しで完了していた。評価バッチは意図解析、コマンド選択、引数生成、安全性確認の4段構成だった。両者のプログラムと入出力が異なるため、バッチで改善しても本番で同じ改善を得られるか判断できなかった。

## 決定

本番 HTTP サービスの `/resolve` とオフライン最適化は、[共通の ResolverProgram と ResolveSignature](../../tools/dspy_common/resolver_program.py) を読み込む。発話、コマンドカタログ、プロンプト版を入力とし、1回の推論でコマンド、引数、選択理由を返す。

## 得失

既存の HTTP 入出力と本番の推論回数を保ち、評価したプログラムに最適化成果物を適用できる。4段構成で可能だった段階ごとの個別最適化はこの方式では行えない。共通プログラムの変更は本番と評価の双方に及ぶため、両方の利用経路と既存成果物との互換性を確認する。
